# Codex Pulse

Windows 桌面 Codex 额度监视器。深色玻璃质感卡片、薄荷青与淡紫双色额度条、迷你悬浮窗与系统托盘。

## 直接运行

构建产物：`release/Codex-Pulse-0.1.0-Windows.exe`，双击启动，无需另行安装 Node.js 或 Codex CLI。首次启动的解压可能需要几秒。

1. 应用优先复用本机 Codex 登录（遵循 `CODEX_HOME`，默认 `%USERPROFILE%\.codex`）。
2. 未登录时点击「连接 ChatGPT 账号」，在浏览器完成官方授权。
3. 右上角图钉控制置顶，横线隐藏到托盘；右下角箭头切换迷你模式。
4. 拖动标题区移动窗口；迷你模式按住品牌或额度区域拖动，单击展开，也支持 Enter / 空格键展开。迷你窗显示所选 Agent 的今日 Token，点击 Token 打开来源选择与详情。
5. 托盘右键菜单可以显示、刷新或彻底退出应用。

「先看看界面效果」与设置中的「体验界面预览」使用**明确标记的演示数据**。退出预览后才展示真实结果。浏览器开发预览无法登录或读取额度。

## 开发

要求 Windows x64、Node.js 22 或更新版本。

```powershell
npm install
npm start
```

其他命令：

```powershell
npm run dev    # 浏览器 UI 预览
npm test       # 额度换算和提醒去重测试
npm run test:desktop # 实际桌面交互冒烟测试（先执行 build）
npm run test:usage-ui # 来源选择与明细交互测试（需要 Playwright Chromium，或设置 PLAYWRIGHT_CHANNEL=msedge）
npm run build # TypeScript 检查与前端构建
npm run pack  # Windows 便携程序
```

## 数据与行为

### 自动使用临期重置卡

另有独立的「余量低于 1% 自动使用」开关，默认开启：任一官方额度窗口的实际剩余比例严格小于 1%（包括 0%）时，**全天**尝试使用一张重置卡，不受纽约工作时段和临期时间限制。以原始数值判断，1% 不触发，0.99% 会触发。两项规则共用串行、防重复和持久化机制，每次使用后重新读取额度再判断；已知到期时间的卡优先，无到期时间但官方明确可用的卡排在其后。官方暂不允许重置或请求失败时，5 分钟后重新核对条件再尝试。

- 默认开启，可在「偏好设置 → 自动使用临期重置卡」关闭。
- 工作时段固定为**每天纽约时间 `America/New_York` 01:00–09:00**，自动适配夏令时，不随系统时区变化。
- 选择距过期至少 1 小时、且位于每天 01:00–08:00 的最晚计划时刻：06:00 到期则 05:00 使用；15:00 到期则当天 08:00；次日 00:30 或 01:30 到期则前一天 08:00。
- 每 30 秒检查一次；错过计划但仍处于 01:00–09:00 且卡片未过期时立即尝试。非工作时间不补用，离线、休眠、退出期间无法执行。
- 临期规则只使用官方明细中有有效 ID、到期时间和支持类型的可用卡片，最早到期优先，每次逐张兑换。界面显示下一次计划，悬停查看最近结果；设置中也可查看最近结果。
- 官方返回 `nothingToReset` 时没有消耗卡片，5 分钟后在有效工作时段内再尝试；是否能使用取决于官方额度资格。网络超时保留同一幂等标识重试，成功后重新读取额度，不凭本地推算重置结果。
- 执行记录写入用户数据目录的 `auto-reset.json`，发送前原子保存；重启复用未确认请求标识，避免重复消费。记录损坏或不可写时停止兑换并显示错误。
- 桌面冒烟测试设置 `CODEX_PULSE_DISABLE_AUTO_RESET=1`，只验证界面；兑换分支使用模拟官方接口测试，不消耗真实卡片。

### 用量与同步

- 内置官方 `@openai/codex` 组件，通过 stdio JSON-RPC 查询账号和额度；启用自动用卡时还会调用 `account/rateLimitResetCredit/consume` 兑换指定的临期卡片，不创建对话或发起模型推理。
- 使用 `100 - usedPercent` 展示剩余百分比；周期长度、重置时间均来自官方响应，不推测剩余请求数。
- 按实际返回的窗口展示：仅有周额度时只显示一张卡片并缩短窗口；迷你模式和通知同样使用实际周期名称。设置页面仍保持完整高度。
- 展示官方返回的重置卡可用张数；有明细时显示已返回的可用卡片中最近的到期日期。未知信息不显示为零张，只有数量时不推测有效期。迷你模式同步显示已知数量。
- 「今日 Token」每 10 秒在工作线程读取本机 OpenCode、Codex、Claude Code、Gemini CLI 用量。点击卡片或迷你窗 Token 可勾选来源（首次默认全选，选择自动保存），展开每个来源查看输入、输出、推理、缓存、会话数及更新时间。未检测到记录、读取失败与部分统计分别标记；总数仅包含所选来源的已知用量。
- 按系统时区当日（00:00 至次日 00:00）统计，自动处理夏令时。OpenCode 按消息完成时间，其他来源按日志用量事件/消息时间归属当日。OpenCode 优先使用消息总 Token，缺失总数且分类完整时求和；Codex 使用累计用量差值，首条或计数重置时使用单次用量；Claude 按消息和请求标识去重；Gemini 兼容 JSON / JSONL，按会话和消息标识去重，回退对话不会扣除已记录的消耗。
- 用量包含缓存，悬停查看输入、输出、推理、缓存读写及会话数；不等同于 ChatGPT 订阅额度扣减。统计独立于官方登录和网络，仅覆盖数据库中仍保留的记录，不覆盖其他设备。数据库不可用时显示错误，不冒充零用量。
- OpenCode 数据库默认位于 `%USERPROFILE%\.local\share\opencode\opencode.db`，遵循 `XDG_DATA_HOME`；可用环境变量 `OPENCODE_DB_PATH` 指定其他文件，也兼容 `OPENCODE_DB`。只查询消息用量元数据，不读取正文或认证表，不修改数据库。
- 兼容新版 `session_message` 与旧版 `message` 消息表；两者同时存在时优先使用新表，避免迁移记录重复统计。
- Codex 读取 `CODEX_HOME`（默认 `~/.codex`）下的 `sessions`、`archived_sessions`；Claude Code 读取 `CLAUDE_CONFIG_DIR`（默认 `~/.claude`）下的 `projects`，包含子 Agent 日志；Gemini CLI 读取 `~/.gemini/tmp/*/chats`，支持 `GEMINI_CLI_HOME` 覆盖用户根目录。日志只在内存解析，向界面传递用量汇总，不保存或展示会话正文。
- 总量包含缓存，但不重复相加已包含的分类：Codex 输入包含缓存、输出包含推理；Claude 缓存独立、推理包含在输出且不单列；Gemini 缓存包含在输入，优先使用记录中的总数。详情中的输入已扣除缓存，OpenCode 沿用其自身分类口径。仅覆盖本地仍保留且包含用量的记录，不代表云端账单或跨设备完整用量。
- 默认 60 秒刷新，可改为 30 秒、2 分钟或 5 分钟。支持手动刷新、恢复唤醒后刷新和额度变更通知。
- 获取失败保留最近一次成功结果并明确标记；重置倒计时归零不会自行恢复为 100%。
- 低于或等于 20%、10% 时提醒，同一运行会话内按账号、额度窗口、阈值去重。
- 设置保存在 Electron 用户数据目录的 `settings.json`，不保存登录凭据。凭据由官方 Codex 组件管理。
- 开机启动仅在打包版本可用。便携 EXE 移动位置后，应关闭并重新开启开机启动选项。
- 透明背景与渐变提供玻璃质感；首版未依赖系统原生 Acrylic 背景模糊。

## 项目结构

```text
electron/main.cjs     窗口、托盘、轮询和系统通知
electron/codex.cjs    官方 App Server 连接及登录协议
electron/quota.cjs    额度转换和提醒去重
electron/preload.cjs  受限桌面 API 桥接
src/main.tsx         悬浮卡片、设置、迷你模式
src/style.css        视觉样式
tests/               额度逻辑与桌面冒烟测试
```

真实账号联调需要在本机完成 ChatGPT 授权，并具备可用的官方网络连接。若账号采用自定义 Codex 配置或组织管理策略，App Server 会遵循这些配置。
